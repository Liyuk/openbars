# Static Pages demo

The public demo at <https://liyuk.github.io/openbars/> is the same read-only UI as
`openbars serve`, published as a static GitHub Pages site. It reads only the
synthetic sample in this directory and never contacts a backend or an external
data source.

- `sample/` — checked-in `/api/v1` responses for the synthetic `TEST*` instruments
  and the fictional `example` quota provider. Generated by
  `scripts/build_pages_demo.py --write-sample`; do not edit by hand.
- `static/static-api.js` — in-memory replacement for the `/api/v1` reads, loaded
  only by the static build. It answers from `sample/` and returns `{"detail": ...}`
  errors for unknown symbols or raw sources.
- `static/demo.css` — the demo skin, layered over the shared `style.css` (tokens,
  header, panels, notice bar, Data sources page, footer). `openbars serve` never loads it.
- `static/content.json` — bilingual copy for the demo-only parts (header, how-to-read
  panel, footer and the **Data sources** page). The builder renders the English markup
  from it and ships the strings to the page script as `window.OPENBARS_EXTRA_I18N`.
  Keep the source list in step with `DATA_SOURCES.md` / `DATA_SOURCES.zh-CN.md`.
- `static/apple-touch-icon.png` — generated by `scripts/render_brand_assets.py`, like the
  logo previews and `docs/images/social-preview.png`.

The static build copies the serve UI shell (`src/openbars/web/static`) and rewrites it
(header, notice bar, footer, extra page, asset paths); the shared `app.js` only gains an
optional string hook that `openbars serve` never defines. The logo comes from
`docs/images/logo/logo.svg` (see `docs/images/logo/README.md`).

The site has four pages: Dashboard, Chart, Flags and Data sources. It always shows the
"Demo with synthetic data" notice with a link to the self-hosting docs, and a GitHub link
in the header.

Regenerate the sample (needs the `http` or `dev` extra):

```bash
uv run --extra http python scripts/build_pages_demo.py --write-sample
```

Build and preview the site locally (standard library only):

```bash
python scripts/build_pages_demo.py --out _site
python -m http.server -d _site 8000   # http://127.0.0.1:8000/
```

The Pages workflow deploys `_site` through the GitHub Actions Pages source; there
is no `gh-pages` branch. To use your own data instead, run `openbars serve` — see
the "Local service" section in the repository README.
